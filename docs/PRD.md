# Flame Contractor（焰之契约者）本机自用版 PRD

> 版本：0.1.0 | 日期：2026-08-26 | 状态：骨架开发基线

## 1. 产品定义

**一句话定义**：一个在用户自己的电脑上运行、集中管理多个本人抖音账号，并以低频、可核验、可暂停的方式完成每日好友续火任务的本地工具。

**品牌文案**：

> 你与它立下契约，每日以一言续之，焰不可熄。

### 1.1 目标用户

- 需要维持少量抖音好友火花的个人用户；
- 拥有一个或多个本人账号；
- 愿意在首次接入及登录失效时本人扫码/验证；
- 更重视“不误发、不重复发”而非大规模和高吞吐。

### 1.2 产品原则

1. **本地优先**：账号会话和运行数据默认不离开本机。
2. **宁可漏发，不可错发**：身份不确定、发送终态未知时停止并提示。
3. **默认防重复**：重复发送保护默认开启，强制重发需要明确操作。
4. **账号隔离**：一个账号异常不阻断其他账号，也不共享浏览器 Profile。
5. **人工接管**：验证码、安全验证、重新登录只能由用户本人完成。
6. **透明运行**：每次任务有状态、时间线和诊断信息，不做不可解释的后台黑盒。

## 2. 范围

### 2.1 P0 功能

#### A. 总览

- 展示今日契约完成数、待执行数、异常数；
- 展示账号健康状态；
- 展示最近任务与需要人工处理的事项；
- 提供“暂停全部自动任务”的总开关（已实现，状态持久化并在后端重启后恢复）。

#### B. 账号管理

- 新建账号记录（只填写本地显示名称，不接收 Cookie/密码）；
- 启用、暂停账号；
- 展示账号状态：
  - `pending_login`：等待首次登录；
  - `healthy`：会话健康；
  - `running`：正在执行；
  - `paused`：用户暂停；
  - `auth_expired`：登录失效；
  - `verification_required`：需本人验证；
  - `dom_broken`：页面结构不兼容；
  - `cooldown`：临时冷却。
- 后续通过独立浏览器 Profile 完成扫码登录。

#### C. 契约对象

- 在指定账号下创建好友契约；
- 记录稳定平台用户 ID（获得后优先使用）与昵称快照；
- 启用/暂停单个契约；
- 绑定消息模板；
- 记录上次确认发送时间和展示用火花天数。

#### D. 消息模板

- 创建纯文字模板；
- 支持受控变量：
  - `{{target_name}}`
  - `{{streak_days}}`
  - `{{weekday}}`
  - `{{date}}`
- 提供实时预览；
- 每条模板具有稳定 UUID 和版本号；
- 不执行任意 JavaScript/Python。

#### E. 调度与任务

- 每账号可配置时区和每日发送窗口；
- 在窗口内生成随机执行时间；
- 同账号并发固定为 1；
- 数据库建立唯一幂等约束；
- 任务状态可追踪；
- Dry Run 只验证账号/目标可定位，不发送消息。

#### F. 运行记录与诊断

- 展示每次任务的状态与阶段；
- 分类失败：网络、登录、验证、目标不确定、DOM 变化、发送终态未知；
- 后续保存脱敏截图和可选 Playwright Trace；
- 日志不输出 Cookie、Storage State、手机号或真实凭据。

### 2.2 P1 功能

- 抖音原生表情和图片消息；
- 每周不同文案与随机文案池；
- Bark、钉钉、邮件通知；
- 导入/导出契约与运行记录；
- Selector bundle 版本管理与本地热更新；
- 抖音官方火花状态扫描刷新（只信任抖音页面扫描结果；已有对象自动刷新，新会话由用户选择导入，不提供手动官方状态输入）。

### 2.3 非目标

- 不做多租户云端 SaaS；
- 不托管陌生用户账号；
- 不做陌生人营销、批量引流或群控；
- 不自动处理验证码或规避平台风控；
- 不提供任意代码宏；
- 不承诺抖音页面改变后永远可用；
- 本轮骨架不接入真实抖音登录和发信。

## 3. 核心用户流程

### 3.1 首次接入

1. 用户启动 Flame Contractor；
2. 新建本地账号记录；
3. 点击“完成首次登录”（后续版本）；
4. 系统为该账号打开独立浏览器 Profile；
5. 用户本人扫码；
6. 系统验证会话并标记 `healthy`；
7. 用户添加一位契约对象；
8. 创建并预览纯文字模板；
9. 执行 Dry Run；
10. 用户确认目标正确后开启自动续火。

### 3.2 每日自动任务

1. 调度器按账号时区生成当日任务；
2. 唯一约束阻止同一消息槽位重复创建；
3. 到达随机时间后 worker 获取账号租约；
4. 验证登录状态；
5. 严格定位好友并二次核对；
6. 输入并触发发送；
7. 观察消息终态；
8. 成功后记录确认时间；
9. 失败时分类并决定有限重试或人工接管；
10. 释放账号租约并更新总览。

### 3.3 异常接管

- 登录失效：暂停该账号，提示重新扫码；
- 验证码/安全验证：暂停该账号，只允许本人处理；
- DOM 不兼容：暂停自动发送，保留诊断 artifact；
- 发送结果未知：标记 `unknown_requires_review`，禁止自动重发；
- 好友身份不确定：不发送，要求重新绑定。

## 4. 页面信息架构

```text
总览
├─ 今日契约
├─ 账号健康
├─ 最近任务
└─ 待人工处理

账号
├─ 账号列表
├─ 新建账号
├─ 登录/验证状态
└─ 账号发送窗口

契约
├─ 按账号筛选
├─ 契约对象
├─ 模板绑定
└─ 最近确认

文案
├─ 模板列表
├─ 安全变量
└─ 预览

运行记录
├─ 任务状态
├─ 尝试时间线
└─ 诊断 artifact

设置
├─ 本地数据目录
├─ 通知
└─ 隐私与保留策略
```

> **当前进度说明（2026-09-11）**：本节是 M1 骨架阶段的历史边界。实际项目已全部完成 M2（扫码登录、严格定位）、M3（真实发送、终态确认、每日防重复）、M4（自动每日调度 + Bark 异常通知）与 M5（图片/原生表情发送、官方火花状态扫描刷新、selector bundle 热更新），并在真实账号上验证通过。最新状态见 [PROJECT_STATUS](../PROJECT_STATUS.md)。

## 5. 骨架版本交付边界

本轮“可运行骨架”必须具备：

- FastAPI 应用、SQLite 核心表和健康接口；
- 账号、契约对象、模板的基础 API；
- 仪表盘聚合 API；
- React/Vite 控制台，可展示真实 API 数据；
- 空状态、异常状态和响应式布局；
- 后端测试与前端类型检查/构建通过。

本轮明确**不具备**：

- 抖音扫码登录；
- Playwright Worker；
- 真实好友搜索；
- 定时任务执行；
- 真实消息发送。

UI 中必须将未实现能力标记为“下一阶段”，不得伪装成可用。

## 6. 验收标准

1. 新环境按 README 可分别启动后端和前端；
2. 首次启动自动建立 SQLite 数据库；
3. 可在 UI 创建一个不含任何敏感凭据的账号记录；
4. 刷新页面后账号仍从 SQLite 返回；
5. 总览数字由后端聚合接口提供，而非前端写死；
6. API 对非法状态、空名称、重复名称给出明确错误；
7. 数据模型具备未来幂等任务的唯一约束；
8. 后端测试全部通过；
9. 前端 TypeScript 检查与生产构建通过；
10. 文档明确安全边界和真实自动化尚未实现。
