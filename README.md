## 启动

### 1. 后端

```powershell
cd backend
python -m venv .venv            # 首次
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt   # 首次
.\.venv\Scripts\python.exe -m playwright install chromium          # 首次
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

首次启动自动执行 Alembic 迁移并创建 `data/flame-contractor.db`。

- 健康检查：<http://127.0.0.1:8000/health>
- OpenAPI 文档：<http://127.0.0.1:8000/docs>

### 2. 前端

```powershell
cd frontend
npm install          # 首次
npm run dev
```

打开 <http://localhost:5173>（开发服务器已代理 `/api` 与 `/health` 到后端）。

### 3. 平台账号首次初始化

- 全新数据库第一次打开控制台时，需要创建首位平台管理员；没有默认用户名或默认密码，密码至少 8 个字符。
- 初始化完成后登录页只保留登录入口，不再开放匿名注册；管理员可在「我的 → 平台用户」创建成员、重置密码或授予管理员权限。
- 忘记密码时由平台管理员在本机重置；当前本地版本不提供无法实际送达的邮件找回流程。
- 旧数据库升级时会保留既有平台用户；仅存在无属主历史业务数据时，兼容认领流程仍使用 `FLAME_BOOTSTRAP_USERNAME` / `FLAME_BOOTSTRAP_PASSWORD`。

### 4. Docker 部署（Windows / Linux）

跨平台和服务器部署使用根目录 `Dockerfile` 与 `compose.yaml`，详见 [Docker 部署说明](docs/DOCKER.md)。Windows 使用 Docker Desktop 的 Linux 容器；Linux 使用 Docker Engine + Compose。容器中使用「截图扫码」登录，数据与浏览器 Profile 持久化到独立卷。

### 5. Windows 原生常驻运行

锁屏后需要继续执行调度时，使用当前用户的常驻监督器：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\runtime\manage_runtime.ps1 -Action Install
```

该命令先构建前端，再通过 Windows Task Scheduler 启动单个 FastAPI 进程；API 和构建后的 React 界面统一使用 <http://127.0.0.1:8000/>。监督器持有系统唤醒请求、每 15 秒检查健康状态，并只重启它自己启动的后端进程。日志和停止/卸载命令见 [`scripts/runtime/README.md`](scripts/runtime/README.md)。

## 扫码登录与定位校验（M2）

1. 在控制台新建账号并添加好友；
2. 点击账号卡片上的「扫码登录」：本机弹出该账号专属浏览器窗口，用抖音 App 扫码；
3. 扫码成功后账号变为「正常」，再点「定位校验」验证每个好友能否被严格定位；
4. 定位校验只定位、绝不发送；身份存疑显示「身份存疑」，登录失效会标记账号。

每个账号使用独立的浏览器 Profile（`data/profiles/<accountId>/`），互不串号。

## 真实发送（M3）

1. 账号「正常」后点「立即发送」→ 弹出发送确认，逐好友展示要发送的文案；
2. 确认后发送：搜索/滚动定位好友 → 二次核对身份 → 输入文案 → 点发布按钮（新版编辑器按 Enter 不发送）；
3. 发送终态确认：编辑框清空 + 气泡内容出现才算成功；无可靠信号记「结果未确认」，当日禁止自动重发；
4. 每天每个好友只发一次（数据库幂等约束兜底）；成功后火花天数 +1；
5. 账号卡片的「强制发送全部」仅供手动补发：会绕过当天同一模板版本的成功记录，并为本次运行创建独立审计任务槽位；身份存疑、结果未知、登录失效或网络不可用仍不会发送，自动调度也不会调用强制模式。
6. 好友列表的「发送」按钮支持**单好友强制发送**：可选模板或直接输入文本（二选一），同样只绕过当天成功记录并独立审计；直接输入文本时任务不引用模板。

## 自动每日发送（M4）

后端启动时自动挂载**进程内调度器**（APScheduler，`app/state/scheduler`）。它只负责「哪个账号今天何时发——账号级随机取时 + 数据库租约 + 同账号互斥 + 崩溃恢复」，实际每个好友的发送仍复用上面已验证的 `run_send` 链路。

- 每个启用账号在它自己的 `send_window`（默认 `20:00-22:00`，按账号 `timezone` 换算）内随机取**一个**发送时刻；
- 到点后由同一个浏览器会话批量发送该账号所有启用好友（同账号并发 = 1，绝不同时开两个会话）；
- 后台每 60 秒轮询一次：为每个启用账号懒生成当日计划（幂等，`(account, business_date)` 唯一），到点抢租约并触发发送；节拍**对齐整分钟边界并留 20ms 余量**，到点比较留 **1 秒容差**——事件循环的定时器可能比目标时刻早几毫秒返回，否则固定时刻（如 `02:22`）会被判成「还没到点」而整整推迟一分钟；
- **好友级准点优先**：设了独立 `send_time_hhmm` 的好友会从账号批量中剔除，并在同一轮 tick 里**先于账号批量**派发（批量等它跑完再开跑）；这样「要准点最先发」的那一个好友能在整点第一个真正发出，而不是被批量抢走浏览器后挤到下一轮（60 秒后）；
- 结果确认走既有终态确认；`partial`/无法确认一律记 `unknown_requires_review`，**绝不自动重发**；
- **固定时刻的宽限期（`FLAME_FIXED_TIME_GRACE_MINUTES`，默认 30）**：账号/好友的固定 `send_time_hhmm` 既是发送时刻也是窗口终点；没有宽限时，派发那一刻本身就已「过期」→ 计划永远被判 skipped、一次都发不出去。宽限期允许在固定时刻之后 N 分钟内仍可派发（默认 30 分钟，`0` 表示不宽限），超过宽限仍未派发才转 skipped；
- **到点是否重发（`FLAME_SCHEDULED_ALWAYS_SEND`，默认关）**：默认保持「每天每个好友只发一次」——当天已成功（含手动强制发送）的好友会被跳过。置 `1` 后，定时任务到点始终发一遍，忽略当天已发送记录（账号批量与好友级准点派发都适用），且使用按业务日固定的独立槽位（`sched<业务日>`）保证重试不会重复发送。无论开关如何，「结果未确认」都绝不自动重发。
- **控制台可调（M10）**：总览「自动调度」卡片新增「定时到点重发」开关与「固定时刻宽限」下拉（不宽限 / 5 / 15 / 30 / 60 / 180 分钟），改动即时生效并持久化到本机数据库（`app_setting` 的 `scheduler.scheduled_always_send`、`scheduler.fixed_time_grace_minutes`），后端重启后仍保持；环境变量只作为首次初始化默认值。两项与「自动同步周期」共用 `PATCH /api/scheduler/settings`，只更新请求里出现的字段。
- **崩溃恢复**：租约过期且计划/好友任务仍停在中间态 → 转「待人工复核」；仅未开始的可重排；
- **暂停**：控制台「自动调度」卡片可一键暂停/恢复全部自动任务；状态持久化到本机数据库，后端重启后仍保持暂停（暂停时手动发送仍可用，不影响）。
- **会话状态自动同步（M9）**：服务启动后首次等待约 1 分钟，之后默认每 24 小时自动扫描一次会话列表；总览可在 1–168 小时内调整周期并持久化到本机 SQLite，`FLAME_AUTO_SCAN_INTERVAL_HOURS` 仅作为首次初始化时的默认值。自动扫描避开发送窗口开始前 15 分钟至窗口结束，避免抢占同一账号浏览器。
- 自动同步只刷新已存在契约对象的官方火花状态，不会静默导入新会话，也不会发送消息；手动「扫描会话列表」仍可随时触发并保留原有导入流程。总览会显示周期、运行中状态和下一次触发时间；执行期间会在全局 `AUTO SYNC` 任务坞显示当前会话、真实处理数和百分比，切换页面或收起面板不会中断。

## 后台会话扫描与任务坞（M8）

「扫描会话列表」由后端后台任务执行，前端 App 层的全局任务坞统一展示发送和扫描进度。切换总览、任务、账号、好友、模板页面，或关闭前端发送/扫描面板，后台任务都不会因此停止。

- 扫描过程中实时展示真实的已发现会话、当前阶段和当前对象；滚动到底前总数未知，不伪造百分比；
- 扫描条目与进度快照持久化到 SQLite，刷新页面或重启后端可读取最近快照；
- 完整成功扫描还会持久化扫描前后对账，固定分为“状态变化 / 无火花 / 新会话 / 未观察到 / 无变化”；最近 10 次记录可只读回看；
- “未观察到”只表示本次完整列表没有看到该对象，不会当作无火花或清空官方快照；无火花删除和新会话导入都必须由用户明确操作；
- 用户取消时保留已经发现的条目，可继续手动导入；失败或取消可显式重试；
- 后端重启会把未完成任务标为「已中断」，不自动续跑、不自动导入新好友、不自动触发发送；
- 自动同步扫描以 `source=automatic` 单独标记，任务坞只提供查看状态和结果，不提供手动扫描的导入、取消或重试操作；
- 扫描结果会区分可读平台号、未观察到身份数据和同名冲突；内部 `sec_uid` 仅作为稳定核对键展示，不再冒充可读抖音号；
- 群聊会从抖音 `imapi` 的 `get_message_by_init` protobuf 提取并校验会话唯一 ID 与群名，写入 `platformConversationId`；同名群聊无法唯一对应时保持未绑定；
- 对已经存在但仍未绑定的普通好友，可单独发起「补采好友身份」任务：后台逐个打开精确好友会话触发官方用户信息接口，切页或收起面板不影响任务；该操作可能将会话标为已读，但绝不发送消息，未观察到可靠响应时保持未绑定；
- 发送时用户严格核对 `platform_user_id`，群聊严格核对 `platform_conversation_id`，两类身份不会混用；
- 扫描只读抖音官方火花状态用于展示/初始化，发送仍以本地 `streak_days` 和严格身份确认作为业务依据。

## 异常通知（M5）

自动调度在无人值守时，若遇到必须人工接管的信号，会推送到你的手机（当前支持 **Bark**）。通知级别按「是否需要立刻处理」分三档：`critical`（响铃，必须处理）、`timeSensitive`（需关注）、`active`（知悉即可）。

**需要人工接管（critical）**

- 账号登录失效（`auth_expired`）——自动续火已停，重新扫码后自动恢复；
- 账号发送出错（重试耗尽）——带上失败原因，如 `DomChangedError`；
- 网络持续不可用（连续 5 轮约 5 分钟）——今日计划已停止，需手动补发；
- 连续失败熔断（M6：连续 N 天失败自动暂停该账号调度）；
- 准点发送时发现登录失效；
- 自动会话同步遇到登录失效。

**需要关注（timeSensitive）**

- 调度发送中断 / 结果未确认（`unknown_requires_review`，多为进程重启或崩溃）；
- 好友级准点发送未完成——点名是哪个好友、卡在什么原因；
- 部分好友结果未确认（重试耗尽）——列出未确认的好友名；
- 发送窗口已结束、计划被跳过（M6）——带上原定时刻；注意该条仅在 `FLAME_WINDOW_EXPIRY_POLICY=skip` 时可能触发；
- 扫码登录失败 / 超时——带上失败原因与等待秒数。

**成功回音（active，`FLAME_NOTIFY_ON_SUCCESS=0` 可关）**

- 账号批量自动续火完成——`成功 12/13 · 跳过 1（今日已发）`，有未成功项时列出好友名；
- 好友级准点发送完成——点名给谁续上了（如固定 `02:22` 的那一条）。

「结果未确认」在任何配置下都不会自动重发，推送里会明确写出这一点。手动「立即发送/强制发送」不推送——那是你本人在操作，页面上就有结果。

配置：在 `backend/.env` 填入你的 Bark 设备地址（只存本机，不入库、不上传）：

```powershell
# backend/.env
FLAME_BARK_URL=https://api.day.app/<你的device_key>
```

未配置时通知自动跳过，调度照常运行。通知级别只接受 `active` / `timeSensitive` / `critical` / `passive`；传入其它值会回退到 `active` 并写一条 WARNING 日志——历史上「账号发送出错」曾因误传 `errors` 被静默降级成最低优先级，现已修正。

## 可靠性机制（M6）

- **失败诊断截图**：发送失败/结果未确认/找不到好友时自动截图存 `artifacts/<账号>/shots/`，工件 JSON 记录页面 URL 与 selector bundle 版本摘要，人工复核不再靠猜；
- **网络预检**：离线时不开浏览器、不消耗当日任务（每 60s 延迟重试，连续 5 轮不可用才终态失败并通知）；
- **登录判定容忍（`FLAME_AUTH_CHECK_TOLERANCE`，默认 2）**：登录判定连续失败达到该次数才把账号标记为 `auth_expired`。单次判定抖动（页面加载慢、临时验证页、网络波动）曾直接把账号判为失效，而调度器会跳过所有非 `healthy` 账号的扫描与发送——一次误判就让账号彻底停摆、只能人工重新扫码恢复（2026-10-10 实测：自动扫描在 8 秒判定窗口内误判，同一时刻会话其实有效）。判定通过（或重新扫码成功）即清零计数；未确认失效时不会推送「请重新扫码」，发送侧也按可重试处理而非终态；
- **登录判定预算（`FLAME_LOGIN_CHECK_TIMEOUT`，默认 20 秒）**：页面打开后等会话列表出现的时长。判定成功立即返回，因此放宽只影响「确实没登录」时的确认耗时，不拖慢正常路径。原为 8 秒，而冷启动实测「打开会话页 4.3s + 判定 1.3s」已逼近上限，慢网络下列表渲染稍晚就会被误判（截图扫码路径用的是 120 秒，同一判据差 15 倍）；
- **页面未加载 ≠ 登录失效**：若判定失败时页面停在 Chromium 错误页（`chrome-error://`），归类为网络问题——发送链路返回 `network_unavailable`（调度器延迟重试、不消耗尝试次数、不改账号状态），扫描/定位校验返回 `error`。否则一次网络抖动会以「请重新扫码」的面目出现，而用户照着扫码也解决不了问题。判定失败同时落一张现场截图（`artifacts/<账号>/shots/*-auth_check_failed.png`）并记录页面 URL，便于事后分辨「确实登出」与「慢/验证页/风控」；
- **有界重试**：发送异常/部分失败在窗口内指数退避自动重试（默认 2 次），复用发送幂等，绝不重复发送；重试耗尽才转人工核；
- **发送冷却**：好友之间默认间隔 3 秒；
- **窗口过期策略**：`FLAME_WINDOW_EXPIRY_POLICY=skip`（默认）——窗口已结束的计划不再深夜补发，转 skipped 并通知；`dispatch` 恢复到点即发；
- **连续失败熔断**：`FLAME_FAILURE_STREAK_LIMIT`（默认 3）——连续 N 次终态失败自动暂停该账号调度（cooldown）并 critical 推送；
- **常驻自恢复**：`scripts\runtime\manage_runtime.ps1 -Action Install` 安装当前用户计划任务，登录自启、失败重试、健康监测并持有系统唤醒请求；旧 `scripts/autostart` 只启动一次，不再推荐；
- **应用日志不再被吞**：`alembic/env.py` 的 `fileConfig` 曾用默认的 `disable_existing_loggers=True`，在启动迁移时把已导入的全部 `app.*` logger 置为 disabled（通知发送失败、扫码登录失败现场、发送诊断都收不到），现改为 `False`；
- **artifacts 保留期**：`FLAME_ARTIFACT_RETENTION_DAYS`（默认 30，0 永久）启动时自动清理过期诊断产物。

## Selector 热更新（M5）

抖音页面随时可能改版，选择器（`app/execution/selectors_bundle.json`）已外置为 **JSON bundle**，运行时惰性检测文件 mtime——页面改版时只需编辑该 JSON（或调接口重载），**无需重启后端进程**，即将到达的登录/定位/发送会自动用新选择器。

```powershell
# 查看当前 bundle / 强制重载（编辑 selectors_bundle.json 后调用）
curl http://127.0.0.1:8000/api/selectors
curl -X POST http://127.0.0.1:8000/api/selectors/reload
```

安全约定不变：无把握的 selector 宁可记 unknown 不误发；改版后必须真实 E2E 复核。

## 原生表情发送（M5）

支持抖音**原生表情（sticker，非图片）**。模板页新建「表情」类型模板，填**表情名称**（如"比心"）与可选分类；发送时 `send_sticker` 点开表情面板、按名称精确匹配表情项、**一点即发**（抖音原生表情单击即发出），随后关闭面板并把焦点点回输入框（避免挡住后续消息）。

- 终态确认与图片一致：**「从我的 + 非头像」新增气泡**锚定，绝不把头像/旧图当成功；确认不了记 `unknown_requires_review`，绝不自动重发。
- 参考 unmev/douyin-auto-fire 的 `send_douyin_sticker()`；选择器已纳入 `selectors_bundle.json`，页面改版可通过热更新适配。
- 真机排查工具：`backend/scripts/probe_sticker.py`（只定位不发，核对表情选择器）、`backend/scripts/probe_sticker_send.py`（真实发送一次）。默认账号为 oinzc。

## 自动调度真机验证（M4）

`backend/scripts/probe_scheduler_e2e.py` 会给指定账号创建一个已到期的当日计划，调用真实 `Scheduler.tick()`，等待 `BrowserManager.run_send` 完成，再核对 `SendSchedule` 与 `SendJob` 的终态。该脚本会真实发送消息，只能在确认后运行；验证完成后应恢复测试模板绑定。

## 文案池（M8）

模板页新增「文案池」类型：一个池挂多条候选文案，每天按**最少最近使用（LRU）**轮换一条发送（绝不连续几天撞同一条）；每条候选可限定生效星期（位掩码，全不选=每天）。预览展示「今天会发的候选」且不消耗轮换顺序。发送链路与文本模板完全一致（受控变量渲染 + 终态确认）。

## 统计与备份（M8）

- 统计：总览页「统计」分区展示 30 天成功率、当前/最长连续成功天数、任务总数；`GET /api/stats/export.csv` 导出任务记录 CSV。
- 备份：总览页「备份全部数据」一键导出全量 JSON（账号/好友/模板+文案池/计划/任务/尝试记录，不含任何凭据）；`POST /api/backup/import` 按 id upsert 导入——空库=完整恢复，已有库=无损合并。Profile 登录态属文件系统层，请随 `data/` 目录一并拷贝备份。

## 截图扫码登录（M8）

账号页提供两种登录方式：**扫码登录**（弹出有头浏览器窗口）与**截图扫码**（headless 渲染登录页，二维码截图在页面内自动刷新，用手机抖音扫屏幕即可）——后者是本机有头窗口渲染异常环境的可靠替代路径，登录判据与正式发送完全一致。

## 安全约定

- 只在本机运行，默认监听 `127.0.0.1`；
- 数据库与日志不保存任何抖音登录凭据；
- 浏览器不做指纹伪装，不自动处理验证码与风控；
- 验证码与安全验证只允许本人处理；
- 未来执行器默认开启防重复，发送终态未知时不自动重发。
